# Contributing to HostTriangle

First off, thank you for considering contributing to **HostTriangle**! Whether you want to fix a bug, improve battery/background stability, or add support for new runtimes (like Node.js or Python), your help is welcome.

---

## Core Design Principles (Please Read First)

Before submitting a Pull Request (PR), ensure your changes align with HostTriangle's core rules:
1. **100% Local Sandbox Privacy:** Do **not** add any third-party analytics, telemetry, crash reporters (e.g., Firebase, Sentry), or cloud upload features. User files and `.env` secrets must never leave the device.
2. **Keep It Lightweight:** HostTriangle is built for students and small projects to run on spare Android phones. Avoid heavy dependencies that bloat the APK size or drain battery unnecessarily.
3. **16 KB Page-Size Compliance:** Any native C/C++ or NDK modifications must maintain 16 KB ELF alignment (`-Wl,-z,max-page-size=16384`) for modern Android compatibility.

---

## AI / LLM Usage Policy

* **No Blind AI-Generated PRs:** Do **not** submit Pull Requests where the entire code or feature is blindly generated by an LLM/AI without human understanding, verification, and real-device testing.
* **Own Your Code:** While using AI tools for small syntax lookups or boilerplate is fine, **you must fully understand every line of code you submit** and be able to explain and maintain it during code review. Low-effort, unverified AI-generated PRs ("AI slop") will be closed immediately.

---

## How to Contribute

1. **Discuss First (For Big Features):** If you plan to add a major feature, open an **Issue** first to discuss your idea so we can make sure it fits the project's scope.
2. **Fork & Branch:**
   * Fork the repository.
   * Create a new branch for your feature or fix (`git checkout -b feature/node-js-support` or `fix/wakelock-drop`).
3. **Code & Test:**
   * Write clean, readable Kotlin/C code.
   * Test your changes on a physical Android device (especially background execution and process auto-restart).
   * Ensure no test tokens, `.env` files, or signing keys are included in your commit.
4. **Submit a Pull Request (PR):**
   * Explain **what** you changed and **why** it helps.
   * Attach screenshots or short screen recordings if your PR changes the UI.
